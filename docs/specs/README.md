# Specs

Machine-readable spec extracts live here: one JSON file per component (plus `tokens.json` and `typography.json`) generated by `tools/extract-tokens` on Day 2.

**Rule:** no value enters this directory from memory, a blog, a port, or a design kit. Every record must cite:

```jsonc
{
  "token": "FilledButton.ContainerHeight",
  "value": 40,
  "unit": "dp",
  "source": "tokens/FilledButtonTokens.kt:31",
  "sourceVersion": "material3:1.5.0",
  "sourceSha256": "d389bb542a1637dc202e715b279a178be1b0d51886234fe2810a92427c07b2a6"
}
```

`typography.json` also carries `defaults` for the shared `TextStyle` attributes (`lineHeightStyle` alignment/trim and Android `platformStyle.includeFontPadding`), because the 30 `TypographyTokens` entries are `DefaultTextStyle.copy(...)` composites. The declaration-by-declaration ledger is `../research/DAY2_COMPOSITES.md`.

Behavioral facts that tokens cannot express (layout rules, state transitions, spring routing, content-padding formulas, min sizes, a11y semantics) belong in a sibling `*.behavior.md` with Compose file:line citations.

Anything unsourced is recorded in `../UNVERIFIED.md` and blocks the component's DONE cell. Generated token TypeScript must come from these files; CI fails on drift.

## Namespace

- **Top-level `*.json`** — owned by `tools/extract-tokens`. Every file is a generated token spec with a source hash; the drift gate verifies it. Do not add non-token JSON at this level.
- **Subdirectories** — other generated spec domains that are not Material3 token values. `shapes/goldens.json` holds the JVM-generated `RoundedPolygon`/`Morph` goldens (see ADR-014); `tools/extract-tokens` does not own it.

Status (Day 7): `tokens.json` and `typography.json` are extracted and drift-gated; `shapes/goldens.json` is generated by `tools/shapes/generate-goldens.sh`. Component specs are added as each component’s research day lands.
