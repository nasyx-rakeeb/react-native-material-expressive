# Known Deviations

Intentional or unavoidable differences from the Compose Material3 1.5.0 reference. **Empty is the goal.** An entry requires evidence (screenshot/diff report path), a reason, and an owner decision reference. Thresholds are never loosened here; a global threshold change requires an approved ADR (Core Rule 8).

The colour system and text harness now exist; component rows will add their own deviations as components land. The **spec-verified** surfaces in `COMPONENT_MATRIX.md` (SideSheet, Banner, Avatar, DataTable, Accordion) have no Compose reference; they are verified against measured m3 spec assertions and a self-regression baseline under ADR-005, and are not deviations by themselves. Any measured miss against their spec file becomes a deviation here.

D-001 is a cross-stack measurement deviation, not a component defect. It is recorded because the literal “cross-stack exact zero” test is not met under faithful Compose defaults. No threshold was changed: the PLAYBOOK §7 gate still uses 0.05% AA-aware pixels, and the Day 3 gate scene remains at 4 px / 0.0009%.

Day 5 extends D-001 to the full 30-role type scale. The faithful run puts **9/30** one-line type scenes inside the 0.05% AA-aware budget (worst: `displayLarge`, 2,745 px / 0.6224%). A second diagnostic run that normalizes the rendering grid (Compose `TextMotion.Animated`, integer physical font sizes, floored offsets) puts **30/30** inside the budget, with **26/30 byte-identical**; the four remaining scenes have a 1 px baseline offset (max 105 AA px / 0.0238%). The matched run is evidence that sizes, weights, widths, tracking, and line heights are correct; it is not a shipping mode. The standard five-scene gate is unchanged and remains green. The faithful-vs-matched interpretation is flagged as `U-25`; no threshold or scene was tuned.

U-25 follow-up (2026-11-26) explains the residual precisely and confirms it is inherent:

- **Pipeline.** RN `TextAttributes.effectiveFontSize` ceils the physical font size; `CustomLineHeightSpan` ceils the line-height span and splits integer leading with `ceil`/`floor`; `TextAttributeProps.letterSpacing` divides by the **integer** font size to get em; and the faithful run also differs in rasterization mode (RN `CustomStyleSpan` sets `isSubpixelText`/`isLinearText`; Compose `TextMotion.Static` hints with subpixel positioning off). Compose keeps the fractional size, line box, and half-leading. Sources and line numbers are in `docs/evidence/day5/typography/compensation/README.md`.
- **Compensation experiment (RN-only, diagnostic).** On the 21 faithful failures, forcing RN's integer font size to the nearest px (C1) leaves **14,121** AA px (2/21); adding a per-role letter-spacing fit (C2) reaches **1,690** (20/21); adding a line-height snap (C3) reaches **1,492** (20/21) but changes the layout height by 1 px and regresses `titleLarge`; fitting the ink-bbox width (C4) reaches **994** (21/21) and zero width-bbox delta, but regresses several roles. All are per-string, per-density fits; none is shippable. No token changed.
- **Matched +1 px baseline.** The four scenes are layout-exact (width/height equal). The predicted baseline offsets are **+0.779 px** (`displaySmall`) and **+0.467 px** (`headlineSmall`). Both stacks use linear+subpixel text in the matched grid, so the integer half-leading baseline offset alone rasterizes as +1 px. `lineHeight` cannot fix it without a 1 px layout-height change. Arithmetic and device metrics: `docs/evidence/day5/typography/baseline/`.
- **Metric proposal.** ADR-010 proposes an ink-normalized text budget — faithful ≤450 AA px / 1,000 ink px **and** ≤3.0 AA px per glyph per font px; matched ≤15 / 1,000 and ≤0.2 per glyph per font px — plus a ±1 px baseline rule. It is **not applied**; the current gate and thresholds are unchanged.

Day 10 measures the converter against that proposal (2026-11-28). The Compose non-linear `FontScaleConverter` is implemented and is the shipping text path; it cuts the 1.3 profiles from 214,694 / 118,751 AA px to 22,658 / 9,480 (−89.4% / −92.0%) without changing the 420/1.0 count (17,798). Across 30 roles × 4 profiles, **119/120** combinations pass the faithful budget. The single miss, `type-label-medium-emphasized` at 320/1.3, is **453.7 per 1,000 ink** against the 450 cap (0.8% over) while its per-glyph value is **2.845** against the 3.0 cap. Because the ADR-010 thresholds are still pending final approval, `Typography` and `Text` are marked `[~] T` in `COMPONENT_MATRIX.md`, not DONE. Evidence: `docs/evidence/day10/typography/`.

**Threshold-independent audit (2026-11-28).** Every diff report now publishes
max channel Δ, mean channel Δ over differing pixels, the count of pixels with
Δ > 2 outside anti-aliased edges, and the count of flat fills with Δ > 2. The
gate itself is unchanged: pixelmatch 0.1 / `includeAA: false` / 0.05% AA-aware
on core scenes. The audit found **no flat fill above Δ 2** in any non-text
scene (Days 3–9), including the two scenes with 22% and 42% exact-different
pixels. Their max Δ 9 is an anti-aliased clip/ripple edge; their flat fills
differ by exactly 1/255 from 8-bit alpha compositing. The only flat-fill misses
are the Day 4 diagnostic text probes, already covered by D-001. No threshold was
loosened or changed; ADR-020 proposes raw guardrails for future approval.

D-002 is a scope boundary, not a regression: the default Compose schemes and the Android API-31 dynamic path are exact, while the opt-in seed generator follows MCU 0.4.0. It must not be described as Compose parity. The API-34+ dynamic role path remains a separate open verification item (`U-24`).

## Policy

1. Attempt a real fix first; three genuine attempts before logging a deviation.
2. Every deviation gets a diff report under `docs/diff-reports/<date>/` and a side-by-side crop.
3. Re-test on every baseline bump (Compose 1.6, CMP 1.13 stable).
4. A deviation that affects a public API needs an ADR, not just a row here.
